# Hardware Test Fixture

Automated hardware tests for the bare-metal Pi 4 kernel, run from a
Linux laptop directly connected to the Pi 4 via USB-Ethernet adapter
and a USB-to-UART bridge.

See [TESTING.md](../TESTING.md) for the full bucket taxonomy
(A=local lints/unit, B=QEMU, C=Pi 4 hardware) and which scripts
drive which bucket.

**One-time tool setup:** see [TOOLS_SETUP.md](TOOLS_SETUP.md) for
granting `tcpdump`, `tshark`, `ethtool`, `arping`, and the venv's
Python the minimum capabilities needed to run without `sudo`.

## Rig

- **Laptop** (the test runner) with:
  - USB Ethernet adapter directly cabled to the Pi 4's RJ45 (no
    switch in between). Default: `enx00e04c0a2bed`, IP `10.0.0.1/24`.
    Override via `HW_TEST_IFACE` / `LAPTOP_IP`.
  - USB-to-UART bridge (CP2102N or FTDI, **3.3 V**) on Pi 4 GPIO
    14/15 (UART0). DTR is wired to GLOBAL_EN for deterministic
    cold-start via `hw_send.py`.
  - `avahi-daemon` running so `wspi5.local` resolves via mDNS.
  - For DHCP-mode runs: `dnsmasq` bound to the USB-Ethernet
    adapter handing out leases from `10.0.0.100-110`. See
    `/tmp/dnsmasq-wspi5.conf` (the rig configuration generated by
    `scripts/dnsmasq-wspi5.conf` or written by hand).
- **Pi 4 (8 GB)** with a chainloader-mode SD built by
  `scripts/mk_sd.sh --chainload <out.img>`. The chainloader sits on
  the SD; the kernel and `network.conf` arrive over UART per
  `hw_send.py --network-conf <conf> kernel8.img`.

## Quick Start

Single-config run (defaults to static-IP mode):

```bash
bash scripts/pre_push_tests.sh
```

This runs Bucket A (lints + unit), Bucket B (QEMU), Bucket C
(hardware L2 + L3 + L4 + L5), and a loose perf gate. The default
`network.conf` is `hw_test/network-static.conf` (Pi at 10.0.0.2).

Dual-config run (static then DHCP, captures both exit codes
independently):

```bash
bash scripts/dual_config_tests.sh
```

Single-bucket runs:

```bash
bash scripts/hw_tests.sh L2          # functional L2 only
bash scripts/hw_tests.sh L2 L3 L4 L5 # all four layers, no perf
bash scripts/hw_tests.sh perf        # all four perf phases
```

Manually push a kernel + config without going through the harness:

```bash
.venv/bin/python scripts/hw_send.py \
    --network-conf hw_test/network-dhcp.conf \
    kernel8.img
```

## Configuration

Most knobs are pytest fixtures or environment variables, set in
`hw_test/conftest.py`:

| Var               | Default                | Purpose                                     |
| ----------------- | ---------------------- | ------------------------------------------- |
| `HW_TEST`         | unset                  | Set to `1` to enable hardware tests         |
| `HW_TEST_IFACE`   | `enx00e04c0a2bed`      | USB-Ethernet adapter on the laptop          |
| `LAPTOP_IP`       | `10.0.0.1`             | Laptop's address on that interface          |
| `PI4_IP`          | resolved per `NETWORK_MODE` | Pin to skip mDNS / lease-file lookup    |
| `PI4_HOSTNAME`    | `wspi5`                | Used to build `<host>.local` for mDNS       |
| `PI4_SERIAL`      | `/dev/ttyUSB0`         | Path to the USB-to-UART bridge              |
| `NETWORK_MODE`    | unset                  | `static` / `dhcp` — gates `@dhcp_only` /    |
|                   |                        | `@static_only` items via the conftest hook  |
| `NETWORK_CONF`    | unset                  | Path to a `network.conf` to push via UART   |

`NETWORK_MODE=dhcp` requires `dnsmasq` running on the laptop and
bound to the USB-Ethernet interface; the post-flash resolver reads
`/var/lib/misc/dnsmasq.leases` directly to avoid avahi cache
staleness.

## Troubleshooting

- **UART debug**: `minicom -D /dev/ttyUSB0 -b 115200`. The
  chainloader's `READY\r\n` is the first line after a DTR reset;
  the kernel prints `Hello from bare-metal Pi 4!` at start.
- **Packet capture**: `tcpdump -i enx00e04c0a2bed -w capture.pcap`
  (caps are pre-set per [TOOLS_SETUP.md](TOOLS_SETUP.md), no `sudo`
  needed).
- **Pi appears wedged**: check `ip neigh show dev enx00e04c0a2bed`
  for stale ARP entries, and `cat /var/lib/misc/dnsmasq.leases` to
  see what IP the Pi was last given.
- **Stale `hw_send.py` from a prior run holds `/dev/ttyUSB0`**:
  `.venv/bin/python -c "from hw_send import kill_stale_hw_send;
  kill_stale_hw_send()"` (the test fixtures sweep this
  automatically at session start and end).
